## 1. Sequencing: offline -> shadow -> canary -> split-traffic A/B
Only one source gave this exact four-stage sequence (GrowthBook, a vendor). Treat as one vendor's recommended practice, not an industry standard.
- Stage 1, offline: lock a dataset, define a grader, record a baseline for the current prompt; move on when gains are consistent, not perfect. https://www.growthbook.io/insights/ab-testing-llms
- Stage 2, shadow: run both variants on live traffic and score them without users seeing a difference (no duration given). https://www.growthbook.io/insights/ab-testing-llms
- Stage 3, canary: expose 1-5% of traffic, watch guardrail metrics 24-48 h, open the full experiment only if nothing alarming. https://www.growthbook.io/insights/ab-testing-llms
- Stage 4, split test: randomize by user (not request), pre-specify duration (two weeks as the floor), be skeptical of early wins (novelty). Use a feature-flag kill switch; consider CUPED. https://www.growthbook.io/insights/ab-testing-llms
- Validate any LLM judge offline before using it on live traffic. https://www.growthbook.io/insights/ab-testing-llms
- Offline vs online definitions: offline = run the app on a predefined dataset before shipping; online = score live production traces. https://langfuse.com/docs/evaluation/overview ; https://docs.langchain.com/langsmith/evaluation-concepts
- Anthropic: build evals that mirror the real task distribution, include edge cases, and favour many auto-graded cases over few hand-graded ones. https://platform.claude.com/docs/en/test-and-evaluate/develop-tests

## 2. Tools
- promptfoo: matrix view comparing outputs of many prompts side by side; runs as CLI, library, or in CI/CD. (Did not confirm llm-rubric on the page.) https://www.promptfoo.dev/docs/intro/
- LangSmith: offline evals on datasets, online evals on production traces, side-by-side comparison of experiments, and pairwise evaluation (judge picks the better of two outputs). https://docs.langchain.com/langsmith/evaluation-concepts
- Braintrust: select two experiments and Compare for per-case scores/outputs; playgrounds for quick iteration, saved as experiments; you define scorers yourself and keep score names consistent. Source is a search summary, pages not opened directly (UNVERIFIED in detail). https://www.braintrust.dev/docs/guides/experiments/run
- Langfuse: datasets and experiments to compare prompt/model/code changes (UI, SDK, CI), online LLM-as-judge on live traces, judge calibration against human labels. Page does not cover prompt-version A/B. https://langfuse.com/docs/evaluation/overview
- OpenAI Evals: JSONL dataset + graders (e.g. string_check) + runs pairing prompt template and model; no dedicated prompt-comparison feature, you create separate runs. The page says the Evals platform goes read-only 31 Oct 2026 and shuts down 30 Nov 2026 (Datasets suggested instead). https://developers.openai.com/api/docs/guides/evals
- Anthropic Console Evaluate tab: test cases added manually, via CSV, or generated by Claude; side-by-side comparison of prompt outputs; 5-point grading; prompt versioning and re-run. From a search summary, docs page not opened (UNVERIFIED in detail). https://docs.claude.com/en/docs/test-and-evaluate/eval-tool
- Anthropic eval guidance: success criteria should be specific/measurable; grading by code, human, or LLM; use a different model as grader, constrain grader output format, validate parsed output. https://platform.claude.com/docs/en/test-and-evaluate/develop-tests
- LaunchDarkly AI Configs: manage prompts/model settings at runtime without redeploy, target configs to segments, roll back instantly, gradual exposure; tracks token usage, satisfaction, cost. The blog does not describe a formal experiments feature; a LaunchDarkly "AI experiments" blog exists in search results but was not opened (UNVERIFIED). https://launchdarkly.com/blog/launch-week-2024-introducing-ai-configs/
- Statsig: AI configs version prompts/models and auto-run evals; "online evals" serve the live version while candidates are graded in background. Docs said AI Evals not accepting new customers (search summary, UNVERIFIED); a claim that OpenAI acquired Statsig (Sept 2025) is UNVERIFIED. https://statsig.com/blog/ai-prompt-experiments ; https://docs.statsig.com/ai-evals/overview
- GrowthBook: open-source experimentation platform with LLM A/B guidance (consistent bucketing, guardrails, CUPED). https://www.growthbook.io/insights/ab-testing-llms

## 5. Online metrics
- Primary: behavioral outcomes (task completion, retention, conversion); BLEU/ROUGE are weak primary metrics. https://www.growthbook.io/insights/ab-testing-llms
- Operational/guardrail: latency, token usage, cost per query. https://www.growthbook.io/insights/ab-testing-llms
- Qualitative: thumbs up/down, satisfaction ratings, session signals. https://www.growthbook.io/insights/ab-testing-llms
- Keep few metrics: article cites 41% false-positive chance with five metrics vs 19% with two; one primary, rest diagnostic. https://www.growthbook.io/insights/ab-testing-llms
- LaunchDarkly names token usage, satisfaction rate, token cost. https://launchdarkly.com/blog/launch-week-2024-introducing-ai-configs/
- Statsig names ratings, score distributions, cost, latency, usage. https://statsig.com/blog/ai-prompt-experiments
